# 用語解説記事の作成ルール

診療放射線技師向けの**用語解説記事**を、`src/content/articles/` に MDX で追加する手順書です。SEO・構造化データ・問題との相互リンクまで含め、公開品質を揃えます。

完成例: `src/content/articles/k-space.mdx`

---

## 絶対に守ること

1. **公式・第三者の記事を転載しない。** オリジナルの解説だけを書く。
2. **用語解説の追加では、基本的なレイアウトと CSS を変更しない。** 通常は MDX（と、スキーマ拡張が必要なときだけ `src/content.config.ts`）だけ触る。記事ページの SEO は `src/pages/articles/[slug].astro` と `src/lib/article-seo.ts` が担う。
3. **記事 ID（ファイル名）と問題 JSON の `terms` を一致させる。** 例: `k-space.mdx` ↔ `"terms": ["k-space"]`。これで問題ページの「関連する用語」と記事ページの「関連する問題」が自動でつながる。
4. **FAQ は frontmatter の `faq` にだけ書く。** 本文 MDX に同内容の FAQ セクションを重複させない（表示・FAQPage 構造化データの単一ソース）。
5. **コミット・push は、ユーザーが依頼したときだけ。**

## 作業前に読むファイル

| ファイル | 用途 |
| --- | --- |
| `src/content.config.ts` | 記事スキーマ（`title`, `description`, `pubDate`, `faq` など） |
| `src/content/articles/k-space.mdx` | 文体・SEO・FAQ の書き方の参照 |
| `src/content/questions/*.json` | リンクさせたい問題の `terms` を確認 |
| `src/lib/article-seo.ts` | 自動出力される JSON-LD（Article / BreadcrumbList / FAQPage） |

## 1. ファイル名と ID

- 保存先: `src/content/articles/{term-id}.mdx`
- `{term-id}` は kebab-case・半角英数字とハイフン（例: `k-space`, `fat-suppression`）
- 対応する類似問題の `terms` 配列と**同じ文字列**にする
- `_template.mdx` は下書き用。公開記事の雛形にしない

---

## 2. frontmatter

```yaml
---
title: "MRIのk空間（k-space）とは｜意味・中心と周辺・国試の要点"
description: "MRIのk空間（k-space）とは、生データが並ぶ空間周波数ドメインです。…"
pubDate: 2026-08-21
draft: false
faq:
  - question: "k 空間とは何ですか？"
    answer: "MRI の k 空間（k-space）とは、**空間周波数**で…"
  - question: "k 空間の中心と周辺の違いは？"
    answer: "…"
---
```

| フィールド | ルール |
| --- | --- |
| `title` | SEO 用。**主キーワード +「とは」+「｜」+ サブトピック**。一覧・関連リンクの短い表示名は「｜」より前が使われる |
| `description` | 120〜160 文字目安。先頭に主キーワードと「とは」。関連語・国試要素を自然に含める |
| `pubDate` | 公開日 |
| `updatedDate` | 大幅更新時のみ（任意） |
| `draft` | 公開前は `true`。RSS・一覧・静的生成から除外される |
| `faq` | 2〜4 問。`answer` は Markdown 可（`**太字**` など）。構造化データ用にプレーンテキストも抽出される |

---

## 3. SEO キーワード設計

1 記事 = 1 テーマに集中する。

| 優先度 | 例（k 空間の場合） |
| --- | --- |
| Primary | `k空間`, `MRI k空間`, `k空間 とは` |
| Secondary | `k-space`, 関連概念（フーリエ変換、中心と周辺 など） |
| 差別化 | `国試`, 初学者向けの落とし穴 |

**表記について**

- 本文では和文と英字の間に**半角スペース**を入れてよい（例: `k 空間`, `MRI 画像`）。読みやすさ優先。
- 検索の表記ゆれ（`k空間` / `k 空間`）は将来のサイト内検索で正規化する。**本文からスペースを消す必要はない。**

---

## 4. 本文構成

おおまかな流れ:

1. **冒頭** … `{用語}とは` で始め、1 段落で定義と読者メリット
2. **見出し（H2）** … 意味・仕組み・現場/国試のポイント・よくある誤解
3. **まとめ** … 3 行以内で要点を再整理

文体:

- 国試受験生と現場初学者の両方が読める粒度
- **高校生でもわかるくらいわかりやすく、例え話を交えながら解説する**（SEO 用語は title / description / FAQ に入れつつ、本文は専門用語・難解な言い回しを避ける。必要なら平易な言葉を先に、略語は後から補足）
- 箇条書き・表は積極的に使う
- 公式問題文・選択肢の転載はしない

### KeyPoint（フロー・数式・要点の囲み）

変換の流れ・関係式・読者に覚えてほしい一行など、本文中で**目立たせたい記述**には `<KeyPoint>` を使う。ライト/ダーク両方で読みやすい角丸の囲みになる。**MDX ファイルでの import は不要**（記事ページでグローバル登録済み）。

```mdx
<KeyPoint>
  k 空間（空間周波数） → 逆フーリエ変換 → 画像空間（位置ごとの信号）
</KeyPoint>
```

- **使う場面** … データの流れ、変換の向き、短い関係式、試験で押さえる一行
- **使わない場面** … 通常の段落、長い説明、プログラムコード（コードは ``` フェンス）
- 実装: `src/components/key-point.astro`

---

## 5. FAQ（frontmatter）

- 検索意図「〜とは」「〜の違いは」に答える質問を 2〜4 個
- 本文で触れた内容の**要約**に留め、本文と矛盾させない
- ページ上では `[slug].astro` が `faq` を「よくある質問」として描画
- `FAQPage` JSON-LD も同データから自動生成

---

## 6. 問題との相互リンク（自動）

| 方向 | 仕組み |
| --- | --- |
| 問題 → 記事 | 問題 JSON の `terms` に記事 ID を書く |
| 記事 → 問題 | 記事 ID と一致する `terms` を持つ公開問題を自動一覧 |

手動で URL を本文に書く必要はない。`terms` の整合だけ確認する。

---

## 7. 自動で付く SEO（実装済み・触らない）

記事ページ公開時に以下が出力される（`draft: false` のみ）:

- `og:type` = `article`
- `article:published_time` / `article:modified_time`
- JSON-LD: `Article`, `BreadcrumbList`, `FAQPage`（faq がある場合）
- canonical, sitemap, RSS

新記事追加だけなら **MDX を書くだけでよい**。

---

## 8. 公開前チェックリスト

- [ ] ファイル名 = 問題 `terms` の ID と一致
- [ ] `title` に主キーワードと「とは」、`description` に検索意図を反映
- [ ] 冒頭が「〜とは」で始まる
- [ ] FAQ は frontmatter のみ（2 問以上推奨）
- [ ] `draft: false` にした
- [ ] 関連問題が記事末尾に表示される（`terms` 連携）
- [ ] 公式文の転載がない
- [ ] `pnpm run build` が通る

---

## 9. 新規作成の手順（エージェント向け）

ユーザーが用語解説記事の作成を依頼したら:

1. このファイルと `k-space.mdx` を Read する
2. 対象用語とリンクさせる類似問題（`terms`）を確認する
3. `{term-id}.mdx` を SEO 方針に沿って作成する
4. 必要なら問題 JSON の `terms` に ID を追加する（未設定の場合）
5. ビルドでエラーがないか確認する
6. レイアウト・CSS・記事ページ実装は依頼がない限り変更しない
