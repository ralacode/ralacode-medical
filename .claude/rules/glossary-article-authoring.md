# 用語解説記事の作成

ユーザーが用語解説記事の作成・編集を頼んだら、作業の**最初に** `docs/glossary-article-authoring.md` を読み、その手順と SEO ルールを**全部**適用して MDX を書く。「『放射線治療　標的体積』をテーマに記事を作成して」のようなテーマだけの一文も、同じ用語解説記事の作成である。方針メモで終えず、title / description / FAQ の SEO、本文の文体、国試の範囲、話し言葉の検品まで通す。ユーザーが「方針だけ」「実装しない」と言ったときだけ、ファイルは作らない。

要点:

- 保存先は `src/content/articles/{term-id}.mdx`。ファイル名は問題 JSON の `terms` と同じ ID（例: `k-space`）。
- **title / description / FAQ** は「とは」で始め、SEO 対策を徹底する。完成例は `src/content/articles/k-space.mdx`。
- **本文の文体**は `src/content/articles/t1-t2-weighted.mdx` の「縦磁化」から「T2 とは」まで。読者のつまずきをかぎ括弧の箇条書きで始め、「とは」の長文定義では始めない。1文1事実。続きは `<br />`、話題の切れ目は空行。定義は平たい言葉を先に、用語名はあと。例えば、で具体物、だから、で見え方を言い切る。です・ます。手順書の「本文の文体」に従う。
- **載せる知識は、診療放射線技師国家試験を解くのに必要な範囲だけ。** それより深い概念、式の導出、歴史、機種ごとの仕様は省く。別テーマになる分量は詰め込まず、必要なら別記事にする。
- **公開前に話し言葉の検品を通す。** 解説口調を話し言葉にする。同じ語尾が 3 回以上続いたら崩す。結論は言い切り、説明は 1 つ削る。「いかがでしたか」と本題前の前置きは削る。段落ごとに、受験生・実習生がその場で言う一言（金額、失敗、感情）を 1 つ。専門語はすぐ分かる言葉にする。最後に初見で「次は読みたくない」理由を 3 つ挙げ、本文から消す。患者の転帰や資料にない体験談は作らない。手順書の「公開前の話し言葉の検品」に従う。
- **国試向け**であることは差別化として残す。特定の回次・問番号（「2026年午前問9の要点」など）を title / description / 冒頭に書かない。記事は用語解説であり、1問の解説ページではない。
- FAQ は **frontmatter の `faq` のみ**。本文に同内容を重複しない。
- 問題とのリンクは `terms` で自動。記事追加だけなら MDX（と必要時のみ `terms` の追記）で足りる。問題ページの「関連する用語」は別タブ、記事ページの「関連する問題」は同じタブ。
- **フロー・数式・要点**など強調したい記述は `<KeyPoint>` を使う（import 不要。記事ページでグローバル登録済み）。コードフェンス ``` はプログラムコード用。
- **高校生でもわかるくらいわかりやすく解説する。** SEO 用語は title / description / FAQ に入れつつ、本文は専門用語・難解な言い回しを避け、必要なら平易な言葉を先に、略語は後から補足する。
- **基本的なレイアウトと CSS は変更しない。** 記事ページの SEO 実装は触らない。
- **Claude Code のローカル**（`CLAUDE_CODE_REMOTE` が `true` でない）は、コミット・push・PR を、この会話でユーザーが頼んだときだけ行う。
- **Claude Code のクラウド**（`CLAUDE_CODE_REMOTE=true`）は、用語記事の MDX を書き終えたら、追加の指示を待たず PR まで送る。`main` へ直接 push しない。ブランチが無ければ `article/{term-id}` を切る。コミットメッセージはリポジトリの `feat:` / `fix:` に合わせ、日本語で書く。PR 本文は `.github/pull_request_template.md`。参考リンクを足したら、先に `pnpm exam:external-links` で台帳を再生成する。PR の前に `pnpm build` と `pnpm lint` を通し、失敗したら直してから開く。
- クラウドの GitHub プロキシは GraphQL を拒む。`gh pr create` は使わない。`gh api repos/{owner}/{repo}/pulls` に `title`、`head`、`base`（`main`）、`body` を渡して REST で開く。push そのものは `git push -u origin HEAD` でよい。force-push しない。
