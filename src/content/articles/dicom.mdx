この記事では、上記のような疑問にお答えします。

医療情報は、アルファベット 3〜4 文字の略語がずらっと並びます。<br />
正直、どれも同じに見えます。<br />
焦らなくて大丈夫です。

## DICOM とは

まず、画像を送るときの決まりごとを見ます。

病院には、CT、MRI、超音波など、いろいろな会社の装置があります。<br />
会社ごとに画像の形がバラバラだと、別の会社のモニタで開けません。

そこで、世界共通の形と、送り方を決めました。

この、「**医用画像を送ったりしまったりするときの共通ルール**」を「**DICOM（Digital Imaging and Communications in Medicine）**」と呼びます。<br />
名前のとおり、「画像（Imaging）」と「通信（Communications）」の決まりです。

例えば、宅配便を思い浮かべてください。<br />
荷物には、宛名や差出人を書いた送り状が付いています。

だから、DICOM のファイルには、画像と一緒に「誰の、いつの検査か」が付いています。<br />
荷物が画素データで、送り状が患者名・検査日などの付帯情報（タグ）です。<br />
2 つは別々ではなく、1 つのファイル（オブジェクト）に入っています。

対象は、単純 X 線だけではありません。<br />
CT、MRI、超音波、核医学など、多くの装置が DICOM を使います。

装置のメーカーは、「この装置は DICOM の何に対応しているか」を書いた書類を付けます。<br />
これを「**適合性宣言書（conformance statement）**」と呼びます。<br />
取扱説明書の「対応機能の一覧」のようなものです。

「DICOM って X 線写真のことでしょ」と思っていると、ここで落とします。

## DICOM と HL7

病院の中を流れる情報は、画像だけではありません。<br />
医師のオーダ、患者の名前や生年月日など、文字の情報もたくさんあります。

画像は DICOM で運びます。<br />
文字の情報は、別の規格で運びます。

この、「**オーダや患者情報など、文字の情報をやり取りする規格**」を「**HL7**」と呼びます。

もう 1 つ、似た顔の言葉があります。<br />
DICOM と HL7 を、どの場面でどう組み合わせればつながるかを示した手引きです。<br />
これを「**IHE（Integrating the Healthcare Enterprise）**」と呼びます。<br />
IHE は新しい規格ではありません。DICOM や HL7 を置き換えるものでもありません。

|  | 何を運ぶか | 役割 |
| --- | --- | --- |
| **DICOM** | 画像 | 画像を送る・保存する |
| **HL7** | 文字の情報（オーダ・患者情報） | 文字の情報をやり取りする |
| **IHE** | 自分では運ばない | DICOM と HL7 の組み合わせ方を示す枠組み |

「IHE って最新の規格なんでしょ」と思うと、選択肢でまんまと引っかかります。

## DICOM の中の言葉

DICOM の中にも、略語が出てきます。<br />
国試では「DICOM に含まれないものはどれか」の形で出ます。<br />
名前と一言だけ押さえれば足ります。

- **SOP クラス** … 「何を（画像など）」と「どうするか（保存・検索など）」の組
- **AE（応用エンティティ）** … 通信の相手の呼び名。PACS、CT 装置など
- **UID** … 世界で重ならない番号
- **VR（値表現）** … 各項目を、文字・数字・日付のどれで書くかの決まり

医薬品の ATC 分類と、病名の ICD-10 は、DICOM ではない別の分類コードです。

カタカナと英語が混ざって、暗記カードを作るのが一番面倒なところです。

## MWM と MPPS

ここが、この記事の中心です。<br />
DICOM で、装置と各システムがやり取りする中身（サービス）を見ます。<br />
引っかけは、ほとんど「どっちからどっちへ」の向きで作られます。

撮影の前に、装置は「今日、誰の、どの検査をするか」を知る必要があります。<br />
RIS から装置へ、患者名と検査内容の一覧（ワークリスト）を配ります。<br />
この、「**撮影前に一覧を配る**」サービスを「**MWM（Modality Worklist Management）**」と呼びます。

撮影が始まったら、装置から RIS へ「始めました」「終わりました」と知らせます。<br />
この、「**撮影の開始と終了を報告する**」サービスを「**MPPS（Modality Performed Procedure Step）**」と呼びます。

- **MWM** … RIS → 撮影装置。撮影前に、患者名と検査内容の一覧を配る
- **MPPS** … 撮影装置 → RIS。「検査を開始した・終えた」を報告する
- **Storage** … 撮影した画像を、PACS へ送って保存する
- **Query/Retrieve** … PACS から、過去の画像を探して取り出す
- **Verification** … 通信の相手とつながるかを確かめる（C-ECHO）

<KeyPoint>
  医師のオーダ（HIS）→ RIS →（MWM）→ 撮影装置 →（Storage）→ PACS
  <br />
  撮影装置 →（MPPS）→ RIS
</KeyPoint>

MWM は「配る」、MPPS は「報告する」です。<br />
装置に向かうのは MWM だけです。<br />
装置から出ていくのは、MPPS と Storage です。

実習で「ワークリストが来てない」と言われて、何のことか分からなかった。<br />
それが MWM です。

## HIS・RIS・PACS

次は、情報をしまう側のシステムです。<br />
3 つとも「〇〇 IS」と似た名前なので、受け持ちで分けます。

病院全体の仕組みが「**HIS（病院情報システム）**」です。<br />
診察の記録（電子カルテ）、検査の依頼（オーダリング）、医事会計が入っています。

放射線部門の受付と記録が「**RIS（放射線情報システム）**」です。<br />
検査の予約、検査の実施情報、照射録を管理します。<br />
撮影装置とも、DICOM でつながっています。

画像の倉庫が「**PACS（医用画像管理システム）**」です。<br />
画像を保管し、読影端末に配り、過去の画像を探して出します。<br />
放射線だけでなく、超音波や内視鏡の画像もしまえます。

|  | 受け持ち | 主な中身 |
| --- | --- | --- |
| **HIS** | 病院全体 | 電子カルテ、オーダリング、医事会計 |
| **RIS** | 放射線部門 | 予約、検査の実施情報、照射録 |
| **PACS** | 画像 | 保管、配信、検索 |

撮影した画像は、RIS ではなく PACS に保存します。<br />
保険証の確認（オンライン資格確認）は、受付や医事会計の仕事です。RIS の機能ではありません。

PACS の画像を、すべて永久に残す法令上の義務はありません。<br />
他院から持ってきた画像を、必ず自院の PACS に取り込む義務もありません。

「RIS も PACS も画像っぽい名前」で迷ったら、画像の倉庫は PACS だけ、と戻ってください。

## 検像とは

撮った画像を PACS に送る前に、技師が中身を確かめます。

- 画像に出ている患者情報が正しいか
- 濃淡（ウィンドウ条件）が合っているか
- シリーズの順番が正しいか
- オーダと、実際に撮った部位が一致しているか

この、「**画像を送り出す前の確かめ**」を「**検像**」と呼びます。

診断医の読影が終わったかどうかは、検像では見ません。<br />
読影は、検像よりあとの別の工程です。

「確認って書いてあるから全部正しそう」と流すと、読影の選択肢を見逃します。

## RDSR と GSDF

最後に、DICOM の仲間の決まりを 2 つだけ見ます。

CT などで、患者さんに当てた線量（CTDI、DLP）を、決まった形の記録で残します。<br />
この、「**線量の記録票**」を「**RDSR（Radiation Dose Structured Report）**」と呼びます。<br />
DICOM の構造化レポートの一つです。

読影用のモニタは、メーカーによって明るさの出方が違います。<br />
同じ画像でも、モニタが変わると見え方が変わってしまいます。<br />
そこで、DICOM が明るさのカーブを決めています。

この、「**どのモニタでも同じ見え方に近づける明るさのカーブ**」を「**GSDF（グレースケール標準表示関数）**」と呼びます。<br />
sRGB や Rec. 709 は、一般の写真やテレビ向けです。GSDF とは別物です。

モニタの品質管理の項目（TG18 など）は、この記事では扱いません。

「sRGB も聞いたことあるし、これでいいか」と選ぶと外れます。

## 国試で問われるポイント

選択肢でよく見る引っかけです。

- MWM は、撮影装置から RIS へ実施情報を返す → **誤り**（正しくは MPPS。MWM は RIS から装置へ一覧を配る）
- 撮影した画像は、RIS に保存する → **誤り**（正しくは PACS）
- IHE は、DICOM に代わる新しい規格である → **誤り**（正しくは、DICOM と HL7 の組み合わせ方の枠組み）
- 院内の画像は、HL7 で送る → **誤り**（正しくは DICOM。HL7 は文字の情報）
- DICOM の付帯情報は、画素データと別のファイルに分ける → **誤り**（正しくは、1 つのオブジェクトにまとめる）
- DICOM の対象は、単純 X 線だけである → **誤り**（正しくは、CT・MRI・超音波・核医学なども対象）
- PACS が保管できるのは、放射線部門の画像だけである → **誤り**（正しくは、超音波や内視鏡の画像も保管できる）
- オンライン資格確認は、RIS の機能である → **誤り**（正しくは、受付・医事会計の機能）

## まとめ

画像は DICOM、文字は HL7 です。<br />
IHE は、2 つのつなぎ方です。

MWM は配る、MPPS は報告する。<br />
装置へ向かうのは MWM です。

画像は PACS にしまいます。<br />
RIS は予約と実施と照射録です。
