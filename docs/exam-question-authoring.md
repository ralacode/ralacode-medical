# 類似問題（アナログ過去問）の作成ルール

診療放射線技師国家試験の**出題意図に沿ったオリジナル問題**を、1問1 JSON で追加する手順書です。新しいエージェント・別モデルでも、このファイルに従って同じ形を再現すること。

既存の完成例は `src/content/questions/2026-78th-am-001.json` 〜 `020.json`。

---

## 絶対に守ること

1. **公式の問題文・選択肢・別冊画像を、リポジトリに転載しない。** 類似問題はオリジナルの文言にする。過去問の転載と捉えられるほど近い言い回しは不可（問6以降は特に、公式の5肢セットをほぼそのまま言い換えるだけ、は避ける）。
2. **基本的なレイアウトと CSS は変更しない。** 問題追加の作業では、見た目・余白・コンポーネント構造・`global.css`・既存の React/Astro のマークアップを触らない。必要なのは JSON（と、PDF 対応表の追記だけ）である。
3. **公式 PDF を git に入れない。** ローカル原本は `exams/`（gitignore）。解説カードからのリンクは厚生労働省の公式 URL を使う。
4. **試験科目について考えるときは `docs/exam-subjects-amendment-2023.md` を参考にする。** 改正前後の科目名と、削られた科目・新設科目の判断に使う。画面に出す ID は `src/lib/exam-subjects.ts`。
5. **コミット・push は、ユーザーが依頼したときだけ。**

`exams/` は gitignore。`docs/` も原則 gitignore で、手順書と科目改正の通知メモだけリポジトリに含める。公式 PDF は入れない。

---

## プロダクト上の位置づけ

- 画面に出すのは **類似問題**（`origin: "analog"`）。公式文ではない。
- 回答後に、対応する過去問の解説・公式正答番号・公式 PDF（と必要なら別冊）を出す。この UI は実装済み。
- `mapsTo` が「どの公式スロットに対応するか」と「公式の正答」を持つ。

演習画面は **単一正解だけ**対応している。公式が「2つ選べ」でも、類似問題は一文択一にする（`src/lib/questions.ts` の `singleAnswer`）。

**採点除外（公式正答なし）** の past question スロットでは、`mapsTo.scoringExcluded: true` を付け、`mapsTo.answer` は書かない。過去問解説の見出しは `sourceOfficialAnswerLabel` により「採点除外（公式正答なし）」になる。`sourceExplanation` の**冒頭**で除外であること・[厚生労働省の除外通知 PDF](https://www.mhlw.go.jp/general/sikaku/successlist/2026/siken06/dl/AM23.pdf) へのリンク・除外理由（公式に詳述がなければ「〜と予想されます」）を書く。具体例は `2026-78th-am-023.json`。

## 1 問を作る手順

ユーザーが「問 N を作って」と言ったら、次の順だけ行う。

### 1. 公式を読む（リポジトリには書かない）

ローカル PDF（gitignore）:

```
exams/2026/2026-78th-am.pdf
exams/2026/2026-78th-am-supplement.pdf
exams/2026/2026-78th-answers.pdf
exams/2026/2026-78th-pm.pdf
exams/2026/2026-78th-pm-supplement.pdf
```

抽出の例（既存の mupdf スクリプトがある場合）:

```text
C:\Users\stsud\AppData\Local\Temp\pdf-page-render\mupdf-extract.mjs
```

- 問題 PDF の該当ページから、**出題の論点**と肢のテーマを把握する。
- 正答表から公式正答を取る（午前問 N は `AMN`）。複数正解は `45` → `[4, 5]`。
- 別冊指定があれば別冊 PDF を描画して所見を把握する。画像ファイルはリポジトリに置かない。
- チャットや JSON に、公式の問題文・選択肢をそのまま貼らない。

2026年午前の問題 PDF は、表紙・注意のあと問1が **PDF 5ページ目**。ページ対応は `src/lib/exam-pdf-page-ranges.ts`（`exam-pdfs.ts` から参照）。別冊は表紙のあと No.1（問4）が 5ページ目。`am2026BookletPages`。

#### PDF ページ番号の決め方（重要）

**問題用紙フッターの `前H-N` / `後H-N` を、PDF ビューアの `#page=N` にそのまま使わない。**

| 用語 | 意味 |
| --- | --- |
| **PDF ページ番号** | 表紙・注意を含むファイル全体の 1 始まり。リンク `#page=N`・`exam-pdf-page-ranges.ts`・`sourceExplanation` は**すべてこちら** |
| **フッター `前H-N` / `後H-N`** | 問題用紙側の通し番号。PDF ページと**一致しないことがある**（第78回午後では多くのページで一致するが、根拠にしない） |

**ページ表を更新するときの手順**

1. ローカル原本 `exams/` または**公式 URL の PDF** を開く
2. ビューア左下の**ページ番号**で、対象の**問番号**が載っているページを確認する
3. その数字を `src/lib/exam-pdf-page-ranges.ts` に書く（`exam-pdfs.ts` は URL のみ）
4. `sourceExplanation` の `#page=N` も**同じ N** に揃える
5. **`pnpm verify:exam-pages`** を実行する（下記）

**自動検証コマンド**

```bash
pnpm verify:exam-pages
```

- `src/lib/exam-pdf-page-ranges.ts` のページ表と、**`#page=` 付き `sourceExplanation`** が一致するか検証する
- ローカルに `exams/2026/2026-78th-{am,pm}.pdf` があれば、フッター（前H-N / 後H-N）の参考表示と、テキスト化された PDF での問番号照合も行う
- 問題文が画像のみの PDF では問番号の自動検出はスキップされる（JSON リンク照合は実行）
- 問題追加・ページ表更新の**必須ステップ**（§7-3 の補助）

### 2. 科目を決める

試験科目について考えるときは、先に `docs/exam-subjects-amendment-2023.md` を読む。令和5年6月の施行規則改正（令和6年4月施行）で、科目の新設・名称変更・統合・削除が決まっている。

実装では `src/lib/exam-subjects.ts` の ID だけ使う。改正後の11科目。削られた科目（診療画像機器学、放射線計測学など）には置かない。

2026年午前の目安（内容で判断。公式の科目ラベルは PDF に無いことが多い）:

| 問 | 科目 ID | 科目名 |
| --- | --- | --- |
| 1〜10 | `shinryo-gazo-kensa` | 診療画像検査学 |
| 11〜 | （核医学の標識・半減期などなら `kakui-gaku`） | 核医学診療技術学 |

MRI・超音波・眼底カメラなどは改正前の「診療画像機器学」寄りでも、その科目は削られているので **診療画像検査学** に置く。

### 3. 類似問題を書く

論点は公式と同じ。文言はオリジナル。

**問題文**

- 公式と一文違い、にしない。
- 問題文でも **強調（`**…**`）** だけ使える。一覧・見出しでは `renderEmphasisHtml` で `<strong>` に変換される（解説ほどの Markdown は不要）。
- 画素値表など行列が必要なときは、stem に数値を書かず **`stemGrid`**（行×列の整数配列）を使う。問題ページで表として表示され、一覧の stem は短文のまま。
- 画像問題（「別冊を別に示す」）は、別冊をサイトに載せない。所見を文章で書いて解けるようにする。
- 断面は「軸位」より **「横断像」** を使う（既存の問6の方針）。
- 計算問題は公式と同じ式を問うが、**数値を変える**。静磁場強度が式に入らないなら、ひっかけとして残してよい。

**選択肢（必ず5つ）**

- 公式の5肢を同じ順・同じ内容で並べない（初期の問は近かったが、問6以降はより離す）。
- 正解の位置は公式と揃えてもずらしてもよい。画面の「正解は n」は類似問題の番号。過去問解説側は `mapsTo.answer`。
- 知識問題は、各肢に `explanation`（Markdown）を書く。計算問題・式選択問題などは正解肢だけでよい（問2・問12の例）。
- 解説の書き方は下記「解説の書き方」を守る。

**sourceExplanation（過去問側の解説）**

- 回答後カード「実際の過去問を解説します↓」に表示する。**類似問題の解説ではなく、公式スロット（`mapsTo`）の解説**。
- 書き方の詳細は下記 **「過去問解説（sourceExplanation）の書き方」** に従う。

**複数正解の公式問**

- 類似は単一正解にする。同じ識別点を、別の問い方（撮像法の同定など）に組み替える（問6の例）。

### 4. JSON を置く

パス:

```text
src/content/questions/{year}-{exam}th-{session}-{NNN}.json
```

例: 第78回午前問11 → `src/content/questions/2026-78th-am-011.json`  
問番号はゼロ埋め3桁。`number` フィールドはゼロなし整数。

### 5. PDF 対応を足す（必要なときだけ）

`src/lib/exam-pdf-page-ranges.ts` 以外の UI は触らない。

- 新しい年・午前/午後の公式 URL が分かったら `officialExamPdfs` / `officialExamBookletPdfs` に追加する。
- 別冊がある問は `am2026BookletPages`（または午後用の表）に **公式の問番号 → PDF ページ（1始まり）** を足す。表に無い問は別冊ボタンが出ない。
- 問題 PDF のページ範囲表は `src/lib/exam-pdf-page-ranges.ts` に足す（`exam-pdfs.ts` は URL のみ）。
- 追記後は **`pnpm verify:exam-pages`** を必ず実行する。

### 6. 確認（スキーマ・表示）

- `pnpm dev` 中なら一覧と `/medical/exams/{year}/{session}/{n}/` で類似問題が出ること。
- 回答後に「実際の過去問を解説します↓」、公式正答、問題 PDF（ページ番号つき）、別冊があれば別冊リンク。
- スキーマ不備だとコレクション全体が空になり全問 404 になる。`mapsTo.answer` は必須。JSON とスキーマを同時に通す。
- レイアウト・CSS を触っていないこと。

### 7. 作成後の必須検証（公式過去問との対応・PDF リンク）

JSON を置いたあと、**ユーザーに渡す前に必ず**次の 3 点を検証する。以前は手作業で行っていた確認を、**作成者（エージェント含む）が毎回実行する**。

#### 7-1. 対応する公式過去問が正しいか

**目的** … 意図した公式スロット（例: 2026 年・第 78 回・**午後**・**問 13**）の類似問題になっているか。別回・別セッション・別問番・別論点の過去問を見ていないか。

**手順**

1. JSON の `mapsTo`（year / exam / session / number）とファイル名（例: `2026-78th-pm-013.json`）が一致しているか確認する。
2. **厚生労働省の公式問題 PDF**（`src/lib/exam-pdfs.ts` の URL）の**該当ページ**を開き、**問番号と論点**を目視する。
   - ローカル原本 `exams/` があれば併用してよいが、**最終判断は公式 URL の PDF** を優先する。
3. `sourceExplanation` の論点・公式 1〜5 番のテーマが、PDF 上の**同じ問**と一致しているか確認する。
4. **午前と午後**、**近い問番**（例: 午前問 13 と午後問 13）の混同がないか特に注意する。

**不合格時** … 論点が違う・問番が違う・セッションが違う場合は、**JSON を作り直す**（誤った `sourceExplanation` だけ直して済ませない）。`exam-pdfs.ts` のページ表も見直す。

#### 7-2. 公式 PDF リンクが別タブで開くか

**目的** … 過去問解説内の公式 PDF リンク（および UI の「公式の問題 PDF」ボタン）が、**ブラウザの別タブ**で開くこと。

**手順**

1. `pnpm dev` で `/medical/exams/{year}/{session}/{n}/` を開き、類似問題に回答して過去問解説カードを表示する。
2. `sourceExplanation` 内の `<a href="…">` リンクをクリックし、**新しいタブ**で PDF が開くか確認する。
3. 解説カード下部の **「公式の問題 PDF（N ページ）」** ボタンも同様に確認する。
4. HTML では `target="_blank"` と `rel="noopener noreferrer"` が付いていること。`sourceExplanation` に手書きリンクを足すときも同様にする。

**不合格時** … 属性不足なら JSON の `sourceExplanation` を修正する。UI ボタン側の問題はレイアウト変更が必要なため、問題追加の範囲外ならユーザーに報告する。

#### 7-3. 公式 PDF が該当ページで開くか

**目的** … リンク先 PDF で、**その問が載っているページ**が表示されること。`exam-pdf-page-ranges.ts` のページ表・`#page=N`・解説の「公式 PDF N ページ」表記が一致していること。

**手順**

1. 7-2 で開いた PDF で、表示ページが **`exam-pdf-page-ranges.ts` に登録した N** と一致するか確認する。
2. そのページに **対象の問番号**（例: 問 13）と、7-1 で確認した**論点**が載っているか目視する。
3. `#page=N` が効かず表紙や別ページになる場合でも、**ページ表・リンクの N が実際の掲載ページと一致しているか**を優先して確認する（Adobe 拡張機能等は `#page=` を無視することがある。ボタン表記の N はユーザーが手動でページ移動する目安）。
4. **`pnpm verify:exam-pages`** が成功すること（ローカル PDF がなくても JSON リンク照合は実行される）。

**不合格時** … ページずれなら `exam-pdf-page-ranges.ts` の範囲表を修正し、JSON の `sourceExplanation` 内リンクの `#page=N` と「N ページ」表記も**同じ値**に揃える。再度 7-1 からやり直す。

#### 検証の記録

- チャットで問題作成を報告するとき、次を**1 行ずつ**触れること（例: 「PM 問 13＝Z スコア、PDF 11 ページ、別タブ・該当ページ確認済み」）。
- 検証に失敗した場合は、**修正後に 7-1〜7-3 を再実行**してから完了とする。

## JSON フィールド

スキーマは `src/content.config.ts`。新規は既存問をコピーしてから中身だけ替えると安全。

| フィールド | 内容 |
| --- | --- |
| `year` | 西暦。2026 |
| `exam` | 回次。78 |
| `session` | `"am"` または `"pm"` |
| `number` | 類似問題の問番号（公式スロットと同じ番号にする） |
| `origin` | 必ず `"analog"` |
| `mapsTo.year` / `exam` / `session` / `number` | 対応する公式スロット |
| `mapsTo.answer` | **公式の正答**（1始まり。複数は配列 `[4, 5]`）。**採点除外で公式正答がない問では省略** |
| `mapsTo.scoringExcluded` | `true` のとき採点除外（公式正答なし）。UI では「採点除外（公式正答なし）」と表示 |
| `subject` | `exam-subjects.ts` の ID（令和6年施行の11科目） |
| `studyTopics` | 省略可（省略時 `[]`）。`exam-subjects.ts` の学習タグ ID 配列。理工学・放射線科学を細分化するとき使う（例：問55–59 → `["hoshasen-seibutsugaku"]`、問60–64 → `["hoshasen-butsurigaku"]`、問65以降は `iyo-kogaku` / `hoshasen-keisoku`） |
| `stem` | 類似問題の問題文（オリジナル） |
| `stemGrid` | 省略可。画素値などの **2 次元整数配列**（各行の長さは同一）。問題文直下に表表示 |
| `choices` | 長さ 5。`text` 必須。`explanation` は Markdown、省略時は空文字 |
| `shuffleChoices` | 省略時 `true`。肢番号そのものに意味があるときだけ `false` |
| `answer` | **類似問題の正答**（1始まり。単一の数） |
| `terms` | 英小文字のスラッグ配列。例 `["dwi"]` |
| `sourceExplanation` | 対応する**公式過去問**の解説。公式文の全文転載はしない。下記ルールに従う |
| `draft` | 公開するなら `false` |

### 最小の形（計算問題の例）

正解肢以外の `explanation` は省略可。`mapsTo.answer` は公式、`answer` は類似。

```json
{
  "year": 2026,
  "exam": 78,
  "session": "am",
  "number": 2,
  "origin": "analog",
  "mapsTo": {
    "year": 2026,
    "exam": 78,
    "session": "am",
    "number": 2,
    "answer": 2
  },
  "subject": "shinryo-gazo-kensa",
  "stem": "（数値を変えたオリジナルの計算問題）",
  "choices": [
    { "text": "0.1" },
    { "text": "0.5" },
    { "text": "1.0", "explanation": "式と代入。" },
    { "text": "3.0" },
    { "text": "10" }
  ],
  "answer": 3,
  "terms": ["slice-thickness"],

```

## 文体

- です・ます調。専門用語はそのまま。
- 問題文は国試調（「〜で正しいのはどれか。」）でよいが、**公式の文をコピーしない**。
- チャットでユーザーに返すときも、公式文を引用しない。論点と類似問題だけ示す。

## 解説の書き方

各肢の `explanation`（類似問題側）と `sourceExplanation`（過去問側）に共通するルール。

**基本**

- **最初に結論**を書く（「なぜ誤り／なぜ正しい」を先に）。
- 1肢あたり **2〜4文**。長くなりそうなら各肢を短くし、詳しい話は `sourceExplanation` に集約する。
- 太字は `**...**`。
- `sourceExplanation` は箇条書き中心（詳細は次節）。

**平易さ（高校生でもわかるくらい）**

- 専門用語は残してよいが、**先に平易な言い換え**を添える。
- **例え話を1つ**入れる（食品の保存、浴槽の排水口、并联の出口など）。1肢に例えを詰め込みすぎない。
- 略語だけで終わらせない。初出は「抗酸化剤（ラジカルスカベンジャ）」のように補う。

**どの肢に書くか**

| 問題タイプ | 各肢の `explanation`（類似問題） | `sourceExplanation`（過去問） |
| --- | --- | --- |
| 知識問題（正誤・識別） | **5肢すべて** | **公式 1〜5 番すべて**に正誤理由（次節） |
| 計算・式選択 | **正解肢だけ**でよい | 式の意味・落とし穴。公式 5 肢すべてが不要なら省略可 |
| 別冊・画像問題 | 所見を文章化して **5肢すべて** | 別冊所見 ＋ **公式 1〜5 番**（次節） |

**用語解説記事との分担**

- 記事が未作成でも `terms` にスラッグを置いてよい。
- 1肢の解説が長くなりそうなときは、肢は短く留め、記事化を検討する（記事作成は別タスク）。

## 過去問解説（sourceExplanation）の書き方

回答後に表示する **「実際の過去問を解説します↓」** 用の Markdown。類似問題の `choices[].explanation` とは**別物**。

### 役割

- **公式スロット**（`mapsTo` の year / exam / session / number）について解く。
- 画面上部の「正解は n です」は `mapsTo.answer`（**公式の肢番号**）に対応する。解説も **1〜5 番は公式の番号** に合わせる（類似問題で正解位置をずらしていても、過去問解説は公式番号のまま）。
- 公式の問題文・選択肢の**全文転載はしない**。各肢は**テーマの言い換え**（短い要約）にとどめる。

### 構成（標準）

次の順で書く。

1. **冒頭 1 文** … `この問は、**論点**を扱います` ＋ 公式 PDF リンク（必要なら別冊リンクも同段落に）
2. **補足段落（任意）** … 別冊所見、類似問題との差（図なしで文章化した旨）、公式が「2つ選べ」だった旨、採点除外など
3. **公式 1〜5 番の箇条書き** … 各肢が **なぜ誤りか／なぜ正解か** を明記
4. **覚え方（任意）** … `- **覚え方** …` で 1 行まとめ

知識問題・正誤問題では **3 の 1〜5 番は省略しない**（午前問98以降・午後問10以降の標準）。

### 公式 1〜5 番の書式

- 1 行 1 肢。`- **N 番** …` で始める（N は 1〜5）。
- 肢の内容は公式を**そのまま引用せず**、キーワードで要約する。
- 正誤ラベルを必ず付ける:
  - 誤り … `→ **誤り**` または `→ **誤り**（正しい内容の補足）`
  - 正解 … `→ **正解**` または `→ **正解**。理由`
- 1 肢あたり **1〜2 文** を目安。長い識別は覚え方に回す。

**例（知識問題）**

```markdown
この問は、**診療放射線技師法**の免許・届出期限です（<a href="…#page=47" …>公式 PDF 47 ページ</a>）。

- **1 番** … 免許証は**都道府県知事**が交付 → **誤り**（**厚生労働大臣**）。
- **2 番** … 登録事項の変更は **30 日以内** → **正解**。
- **3 番** … 免許取消後の返納 **30 日以内** → **誤り**（**10 日以内**）。
…
- **覚え方** … **30 日**＝登録変更・死亡届／**10 日**＝免許証の返納。
```

完成例: `2026-78th-am-098.json`、`2026-78th-pm-011.json`、`2026-78th-pm-012.json`。

### 別冊・画像問題

- 冒頭または箇条書きの先頭に **別冊所見** を一般化して書く（画像の転載はしない）。
- 別冊 PDF へ `<a href="…">` リンク。問題 PDF リンクと併記してよい。
- 類似問題が図なし・文章化している場合は、その旨を 1 行書く（`本サイトの類似問題は図を載せられないため、…`）。
- 各肢は **公式が何を選ばせていたか**（部位名・所見・順序など）を要約し、正誤理由を付ける。

完成例: `2026-78th-pm-010.json`、`2026-78th-am-088.json`。

### 計算・式選択問題

- 公式 5 肢すべてが不要なときは、式・代入・落とし穴に絞ってよい。
- それでも **公式正答番号** と **なぜその式・数値になるか** は書く。

### 公式が「2つ選べ」のとき

- `mapsTo.answer` は `[3, 4]` のように配列。
- 過去問解説では **正解だった公式肢を両方「正解」** と書く。
- 類似問題を単一正解に組み替えた場合、その旨を冒頭か覚え方付近に 1 行書く。

### 採点除外

- `mapsTo.scoringExcluded: true` の問は、冒頭で除外であること・[除外通知 PDF](https://www.mhlw.go.jp/general/sikaku/successlist/2026/siken06/dl/AM23.pdf) へのリンク・理由（推定なら「〜と予想されます」）を書く。
- 具体例: `2026-78th-am-023.json`。

### PDF リンク

- 問題 PDF は `<a href="公式URL#page=N" target="_blank" rel="noopener noreferrer">公式 PDF N ページ</a>`。
- URL とページ番号は `src/lib/exam-pdf-page-ranges.ts`（および `exam-pdfs.ts` の URL）に合わせる。
- 別冊は `officialExamBookletPdfLink` が出るよう `exam-pdfs.ts` の別冊表を先に登録する。

### 類似問題の解説との分担

| 項目 | `choices[].explanation` | `sourceExplanation` |
| --- | --- | --- |
| 対象 | **類似問題**の各肢 | **公式過去問**の各肢（1〜5 番） |
| 肢番号 | 類似問題の並び（シャッフル可） | **公式の 1〜5 番**（固定） |
| 内容 | 類似問題の stem / 肢に即した解説 | 公式の論点・公式肢の正誤 |
| 重複 | 同じ説明のコピペは避ける | 類似で触れない公式肢の識別を厚く書く |

### 用語・表記

- 画像の歪みは **アーチファクト**（「アーティファクト」は使わない）。
- 断面は **横断像**（「軸位」よりこちらを優先）。
- です・ます調。`sourceExplanation` 内も Markdown の `**太字**` を使う。

### チェック（過去問解説）

- [ ] 公式 1〜5 番がすべて載っている（計算問題など省略例外を除く）
- [ ] 各肢に **正解** または **誤り** が付いている
- [ ] 番号は **公式** の 1〜5（類似の `answer` 位置と混同していない）
- [ ] 公式の問題文・5 肢の全文を転載していない
- [ ] 公式 PDF（と別冊）リンクがある
- [ ] `mapsTo.answer` の正答番号と解説の **正解** 表示が一致している

## やってはいけないこと（問題作成時）

- `src/components/`、`src/layouts/`、`src/styles/global.css`、ページのマークアップを、問題追加のついでに直すこと。
- 検索 UI や PDF ボタン、パンくず、テーマを「ついでに改善」すること。
- 公式 PDF を `public/` に置く、別冊画像をコンテンツに埋め込むこと。
- `getPublishedQuestions` を空配列にフォールバックして 404 を隠すこと（スキーマエラーが見えなくなる）。
- 複数正解のまま `answer: [4, 5]` で類似問題を公開すること（演習画面が未対応）。

ユーザーがレイアウト変更を明示的に頼んだときだけ、見た目を触る。

## 公式 PDF リンク（実装済み・触らない）

回答後の解説カードは次を自動表示する。

- 問題 PDF: `officialExamPdfLink`（`#page=N`）。ボタン表記は「公式の問題PDF（Nページ）」。
- 別冊: `officialExamBookletPdfLink` に問番号があるときだけ。
- Adobe 拡張機能は `#page=` を無視することがある。ページ番号をボタンに出してある。これ以上の回避（PDF の再ホスト等）はしない。

新しい年の PDF URL がユーザーから出たら、`exam-pdfs.ts` の表だけ更新する。
