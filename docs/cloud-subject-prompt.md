# Cloud 科目プロンプトの生成

科目ごとの Cloud 指示を、毎回ゼロから作文しない。マニフェストを読んで固定テンプレを埋め、**貼る用の本文だけ**を出す。

ローカルの対話向け。Cloud Agent には、この手順でできた本文だけを貼る。問題 JSON は作らない。コミットしない。公式 PDF は開かない。

---

## いつ使うか

ユーザーが「次の科目のプロンプト」「○○年午前の次の塊」など、**Cloud に貼る指示文**を頼んだとき。

類似問題そのものの作成を頼まれたら、このファイルではなく `docs/exam-question-authoring.md` に従う。

---

## 読むもの

| ファイル | 用途 |
| --- | --- |
| `src/data/exam-manifests/{year}.json` | 問番号・科目・複数正解・別冊・計算・採点除外・学習タグ |
| `src/content/questions/{year}-*.json` | 既にある問（触るな、と書くため） |
| `src/lib/exam-subjects.ts` | 科目 ID の日本語名 |
| このファイル | 出力の形 |

`docs/exam-question-authoring.md` の全文はプロンプトに貼らない。「最初に Read せよ」と一行書く。

---

## やってはいけないこと

- 公式 PDF・`exam:pdf-text` を読む
- 公式の問題文・選択肢・別冊の内容をプロンプトに書く
- 科目範囲を「10問ごと」で推測する
- 手順書全文をプロンプトにコピーする
- 1本のプロンプトで複数科目・複数 PR を依頼する

---

## 塊の決め方

1. 対象年のマニフェストを、指定セッション（午前/午後）で問番号順に見る。
2. 連続する同じ `subject` を 1 塊とする。`studyTopics` が変わっても科目 ID が同じなら、原則 1 塊。
3. 既に JSON がある問は塊から外す。
4. 1 塊が **12 問を超える**（例: 理工学 55–72）ときは、学習タグまたは 10 問前後で分割し、ブランチに問番号を付ける。分割したらプロンプトに「科目は同じ、塊だけ分けた」と書く。
5. ユーザーが問番号や科目を指定していれば、それに従う。

ブランチ:

- 1 科目 1 塊: `q/{year}-{exam}th/{subject-id}`
- 分割した塊: `q/{year}-{exam}th/{subject-id}-{session}-{from}-{to}`  
  例: `q/2025-77th/rikogaku-hoshasen-am-55-59`

---

## マニフェストから抜く表（公式文は書かない）

対象の各スロットについて:

| 抜くもの | プロンプトへの書き方 |
| --- | --- |
| `officialAnswer` が配列 | 「問Nは公式が複数正解。類似は単一正解。残した正答の文は誤りに書き換える。stem の『最も』で逃げない」 |
| `hasBooklet: true` | 「問Nは別冊あり。図は文章化。別冊画像は載せない」 |
| `kind: calculation` | 「問Nは計算。公式と同じ式、数値は変える」 |
| `scoringExcluded: true` | 「問Nは採点除外。手順書の除外の書き方に従う」 |
| `studyTopics` | ID をそのまま書く |
| 該当なし | 「この塊に計算はない」など、無いものは一行で否定する |

論点が欲しくなったらマニフェストの `topic` の 1 行だけ使ってよい。公式の肢の要約にしない。

---

## 出力

前置きは短くてよい（科目名・問番号・「新しい Cloud Agent に貼る」）。本文は次のテンプレを埋め、コードフェンス 1 個にする。

```text
Cloud Agent として作業してください。main へ直接 push しない。新しい実行として始める。前の科目の Agent は再開しない。

今回: {year}年（第{exam}回）{午前|午後} 問{from}〜問{to}。
科目 ID はマニフェストどおり {subject-id}（{日本語名}）。
{studyTopics があれば: 学習タグはマニフェストどおり …}
ブランチ: {branch}
成果物: 類似問題 JSON だけ（src/content/questions/{year}-{exam}th-{am|pm}-{NNN}.json 〜 {NNN}.json）。
ページ表・マニフェストは触らない。足りなければ PR 本文に書いて止める。
厚労省公式以外の参考 URL は足さない（external-links.md の衝突を避ける）。

最初に docs/exam-question-authoring.md を Read し、その手順に従う。
- 公式の問題文・選択肢・別冊画像・exam:pdf-text の出力を、JSON・PR・チャットに転載しない。
- 公式 PDF は pnpm exam:pdf-text / exam:pdf-render で読む。
- {year}年は祖父化しない。知識問題は sourceExplanation に公式1〜5番の正誤と #page= を書く。
- 類似は単一正解。公式が「2つ選べ」でも一文択一。
- {複数正解の問があればここに列挙。残した正答文は類似の stem の下でも誤りであること。『最も』『典型』で正しい肢を2つ残さない。}
- 言い換えはよいが、choices の並びは公式の1〜5と同じにしない。answer は並べ替え後。sourceExplanation の番号は公式のまま。
- 記事リンクは choices[].text に置かない。
- 既にある問（{既存の問番号}）と、今回の範囲外の問は触らない。

{別冊・計算・採点除外・「この塊にはない」の行}

終わったら検査を全部通して Draft PR を開く。PR 本文は .github/PULL_REQUEST_TEMPLATE/exam.md。
公式文は PR に貼らない。
知識問題の5肢真偽表は、類似 JSON の並びで、stem の下で正しい肢がちょうど1つであることを示す。
```

空欄は埋め、該当なしの行は削除する。プレースホルダを残さない。

## 出したあとの確認

- [ ] 公式の問題文・5肢・PDF 引用がプロンプトに無い
- [ ] 問番号と科目 ID がマニフェストと一致
- [ ] 複数正解・別冊・計算・除外の問番号が漏れなく、無いものは「ない」と書いてある
- [ ] 既存 JSON の問を「触るな」と書いてある
- [ ] 1 科目（または明示した1塊）だけ
- [ ] 「新しい Cloud Agent」と書いてある
